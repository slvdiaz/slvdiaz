About me
I'm Salvador Diaz, a Cybersecurity Engineering student and independent security researcher interested in understanding how systems fail — and how to make them harder to break.
My work and learning are focused on web and API security, bug bounty research, Red Team methodologies, Linux systems, and remote infrastructure. I enjoy investigating complex attack surfaces, tracing issues across application layers, and turning technical findings into clear, actionable reports.
I'm also interested in developing practical security tools, automating repetitive research tasks, and sharing useful work with the cybersecurity community.
Focus areas
Area	What I'm interested in
Web Pentesting & AppSec	Application logic, API security, authentication, authorization, and access-control flaws.
Bug Bounty Research	Independent security testing, vulnerability analysis, responsible disclosure, and technical reporting.
Red Team	Attack-surface discovery, realistic attack paths, and understanding how weaknesses can be chained.
Linux & Infrastructure	Linux systems, remote servers, network services, system hardening, and operational security.
Security Tooling	Building scripts and tools that make security testing more useful, repeatable, and accessible.
Mobile & SDK Security	Client/server trust boundaries, traffic analysis, runtime inspection, and application behavior.
Selected security research
I have participated in private bug bounty and coordinated-disclosure programs. My research has covered areas including:
Broken Object Level Authorization (BOLA / IDOR): cross-account access to API resources and actions.
API authorization and business logic: examining how identity, permissions, and server-side decisions are enforced.
Information disclosure: identifying unintended exposure of user data, internal application details, and runtime configuration.
Mobile and SDK security: inspecting client/server communication, request flows, and trust boundaries.
Infrastructure exposure: mapping externally reachable services and evaluating the risks of exposed origin infrastructure.
Some findings have been validated, rewarded, and addressed by program teams. Program names, affected assets, report references, and reproduction details are intentionally omitted while the underlying reports remain private.
